## Question

You are writing the control loop for an agent built on the Claude API. Which TWO practices are correct for deciding when the loop continues or stops? (Choose 2.)

## Options

- **A)** Stop as soon as the response contains any assistant text content.
  - **Rationale:** A single response can contain a text block and a `tool_use` block together. Text being present does not mean the model has finished. Checking for text as a completion signal is a named anti-pattern.
- **B)** Stop when the assistant's text contains phrases like "I'm done" or "task complete".
  - **Rationale:** Parsing natural-language signals is a named anti-pattern. The wording varies, and the model may say "done" mid-task or never say it at all. It is not a protocol signal.
- **C)** Stop after a fixed 10 iterations as the primary stopping mechanism.
  - **Rationale:** An arbitrary iteration cap as the main stop rule is a named anti-pattern. It can cut real work off early or waste turns on simple tasks. A cap as a safety backstop is different; as the primary rule it is wrong.
- **D)** Append each tool result to the conversation history before sending the next request.
  - **Rationale:** Correct. The model can only reason about results that are in its context. Adding each tool result to the history is how it decides the next step.
- **E)** Continue the loop while `stop_reason` is "tool_use", and stop when it is "end_turn".
  - **Rationale:** Correct. `stop_reason` is the model's own signal. "tool_use" means it wants a tool run and the loop should continue; "end_turn" means it has finished.
