## Question

A developer wrote up the team's API conventions — error envelope shape, pagination style, how to version endpoints — and Claude Code has followed them reliably for that developer for months. The file lives at `~/.claude/CLAUDE.md`.

A teammate joins, clones the repo, and reports that Claude Code ignores all of it. Nothing about their setup is broken; they are working in the same repo on the same branch.

What is the fix?

## Options

- **A)** Send the teammate the file and have them save it to their own `~/.claude/CLAUDE.md`.
  - **Rationale:** Makes the symptom go away for one person and guarantees the problem returns. Every new joiner needs the same manual step, and the moment anyone edits their local copy the team's conventions silently diverge with nothing to reconcile them. A convention that lives in N private copies is not a shared convention.
- **B)** Keep the file where it is and add an `@import` line in the project's root `CLAUDE.md` pointing at `~/.claude/CLAUDE.md`.
  - **Rationale:** `@import` is real and is the right tool for modular memory — but this import target is outside the repository. On the teammate's machine, `~` resolves to *their* home directory, where these conventions do not exist, so the import brings in nothing useful. It also wrongly implies a root `CLAUDE.md` needs an import to do anything: a committed root `CLAUDE.md` is loaded on its own.
- **C)** Move the conventions into a `CLAUDE.md` at the repo root and commit it.
  - **Rationale:** Correct. `~/.claude/CLAUDE.md` is user-level: it applies to everything that one user does across all projects and is never shared through version control. Project-level `CLAUDE.md` is the mechanism for team-shared instructions — a committed root `CLAUDE.md` is loaded automatically for anyone working in the repo, so the teammate gets it on clone with no setup. This is the hierarchy diagnosis the exam guide (T3.1) describes: the instructions were at the wrong scope, not missing.
- **D)** Move the conventions into `.claude/rules/api-conventions.md` with frontmatter `paths: ["src/api/**"]` and commit it.
  - **Rationale:** Right about committing, wrong about scoping. Path-scoped rules are for conventions that apply only to a subset of files. These conventions govern how the whole codebase talks to the API — clients and tests included — so a glob limited to `src/api/**` means they go missing exactly when someone writes a consumer outside that directory. Use path scoping when there is a real file-path condition; these conventions are universal.
