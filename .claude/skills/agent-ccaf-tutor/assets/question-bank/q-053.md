## Question

Your system extracts event metadata (date, location, organizer, `attendee_count`) from news articles using a JSON schema with all nullable fields. During evaluation, you observe the model frequently generates plausible but incorrect values for fields not mentioned in the article—for example, outputting "500" for `attendee_count` when the source contains no attendance information.
What's the most effective way to reduce these false extractions?

## Options

- **A)** Add a post-processing step using a second LLM call to verify each extracted value exists in the source document.
  - **Rationale:** Expensive second pass for a behavior you can correct at the source — tell the model to return null when the field isn't stated.
- **B)** Upgrade to a more capable model tier with improved instruction-following to reduce hallucination tendencies.
  - **Rationale:** Adds cost and still doesn't tell the model your policy — returning null instead of inventing.
- **C)** Make all schema fields required (non-nullable) with strict validation rules to ensure the model only outputs verifiable data.
  - **Rationale:** Required fields force the model to invent values when information is missing — the opposite of what you want.
- **D)** Add prompt instructions to return null for any field where information is not directly stated in the source.
  - **Rationale:** Correct. The fields are already nullable; the model just needs an explicit instruction to prefer null over a plausible guess. This is the standard fix for schema-aware hallucination.
