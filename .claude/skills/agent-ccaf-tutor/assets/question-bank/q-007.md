## Question

An engineer who just joined the team asks the agent to help them understand the authentication and authorization architecture before making security improvements. The codebase has 800+ files across multiple services.
What exploration strategy will most effectively build understanding, given Claude built-in tools and context limits?

## Options

- **A)** Use Grep to find authentication entry points, read those files, then follow imports and function calls to map the auth flow incrementally.
  - **Rationale:** Correct. Start at entry points (login, token verify, middleware), then trace outward following real code edges. Incremental, grounded, fits within context limits.
- **B)** Read any CLAUDE.md and README files first, then ask the engineer to specify which 10-15 files are most important for understanding the auth system.
  - **Rationale:** The engineer just joined — they probably don't know which files matter. That's exactly what the agent is supposed to help with.
- **C)** Launch parallel subagents to explore different services simultaneously, then synthesize their findings into an architectural overview.
  - **Rationale:** Without knowing where auth lives, fan-out explores too broadly and subagents duplicate and miss cross-service flows.
- **D)** Read all files containing "auth", "login", "permission", or "token" in their content or filename.
  - **Rationale:** Those keywords hit a huge amount of unrelated code across 800+ files and drown context in noise.
