## Question

A team has two skills in `.claude/skills/`.

`dep-audit` walks the full dependency tree and prints every package, version and licence it finds. It finishes in about 8 seconds and emits roughly 3,000 lines.

`perf-baseline` runs the benchmark suite. It takes about 11 minutes and finishes by printing four numbers.

The team can add `context: fork` to one of them. Which, and why?

## Options

- **A)** `dep-audit`, because its output volume would flood the main conversation.
  - **Rationale:** Correct. `context: fork` runs the skill in a separate subagent context; only its result comes back, so its output does not pollute the main conversation. The problem it solves is output volume, not runtime. 3,000 lines of tree output crowds out the work in progress and pushes earlier context toward the lost-in-the-middle zone, while the useful takeaway is a short list of findings. Fork it and the main thread receives the summary instead of the dump.
- **B)** `perf-baseline`, because a skill that runs for 11 minutes should be isolated from the main conversation.
  - **Rationale:** The duration trap. Runtime is irrelevant to what `context: fork` does — forking isolates *context*, not execution time, and an 11-minute skill that returns four numbers costs the main conversation almost nothing. Waiting is not a context problem.
- **C)** `perf-baseline`, because benchmark runs should not be able to modify files in the main working tree.
  - **Rationale:** Conflates two different frontmatter fields. Restricting which tools a skill can use is what `allowed-tools` is for (in exam-guide terms; current Claude Code uses `disallowed-tools` for that). `context: fork` isolates context, not permissions — a forked skill is not sandboxed away from the filesystem.
- **D)** `dep-audit`, because forking lets it run in parallel with whatever else is happening in the main conversation.
  - **Rationale:** Right skill, wrong reason — and the reason matters, because it would lead to forking the wrong skills later. The purpose of `context: fork` is keeping verbose output out of the main context, not concurrency.
