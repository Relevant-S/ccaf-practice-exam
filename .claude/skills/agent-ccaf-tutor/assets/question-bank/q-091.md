## Question

You are designing the JSON schema for an invoice extraction tool.

- The purchase-order number is often absent from invoices.
- `payment_terms` is usually one of five standard values, but sometimes something unusual.
- A few invoices state their terms so vaguely that even a human can't tell which value applies.

Which THREE schema decisions are correct? (Choose 3.)

## Options

- **A)** Make every field required so each extraction is complete.
  - **Rationale:** When the value is not in the document, a required field pushes the model to invent one to satisfy the schema. "Complete" output full of made-up purchase-order numbers is worse than an honest gap.
- **B)** Set `tool_choice` to "auto" to guarantee the structured output is returned.
  - **Rationale:** "auto" lets the model reply in text instead of calling the tool, so it guarantees nothing. "any" or forcing the specific tool is what guarantees a tool call. This is also not a schema decision.
- **C)** Define `payment_terms` as an enum of the standard values plus "other", with a `payment_terms_detail` string.
  - **Rationale:** Correct. The enum keeps the common values consistent. "other" plus a detail string captures unusual terms without losing them, and new values do not break the schema.
- **D)** Add an "unclear" enum value for payment terms that are genuinely ambiguous in the source.
  - **Rationale:** Correct. An "unclear" value records that the source is ambiguous, instead of forcing the model to guess one of the standard values. Downstream steps can then route those invoices for review.
- **E)** Instruct the model to map unusual terms to the closest standard enum value.
  - **Rationale:** This loses information. The real terms disappear and the record looks normal, so nobody notices the error.
- **F)** Make `po_number` optional (nullable) so the model returns null when it is absent.
  - **Rationale:** Correct. The field is often missing from the source. A nullable field lets the model say "not present" instead of fabricating a value to fill a required field.
