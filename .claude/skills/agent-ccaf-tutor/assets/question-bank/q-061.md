## Question

A multi-agent research system (coordinator + web search agent + document analysis subagents + synthesis subagent) produces a market sizing brief on enterprise SaaS spending. Document analysis subagents have extracted Annual Recurring Revenue (ARR) figures from 22 vendor 10-K filings dated between 2022 and 2025.

The synthesis subagent's current matching logic:

- If two extracted ARR figures differ by more than 5%, classify as `conflict` → route for human review.
- If two extracted ARR figures are within 5% of each other, classify as `match` → include in the brief as a corroborated datapoint, no human review.

In a draft brief, the synthesis agent reports: *"Two vendors anchor enterprise ARR near $4.2B (corroborated across sources)."* On inspection, one figure is from a 2022 filing; the other from a 2025 filing.

What's the most significant architectural flaw in this synthesis-agent design?

## Options

- **A)** The 5% threshold is too tight — financial figures fluctuate quarter-over-quarter, and a wider band (15–20%) would reduce false-positive conflict flags routed to human review.
  - **Rationale:** Adjusting the threshold misses the structural issue. The defect isn't the *width* of the matching band; it's that the band is applied across figures from different time periods in the first place. A wider threshold would mask more false agreements, not fewer.
- **B)** The matching logic needs a third category — figures from different reporting periods should be classified as **temporally non-comparable**, distinct from `match` or `conflict`, which both implicitly assume the figures describe the same time window.
  - **Rationale:** Correct. The exam guide (T5.6) says publication/collection dates must be carried through structured outputs so temporal differences are not misread. A binary match/conflict split silently treats a time mismatch as confirmation when the values happen to agree, and as contradiction when they don't. The fix is structural (a third bucket), not a different threshold.
- **C)** Conflicts should not be routed to human review by default — the synthesis agent should attempt to reconcile contradictions by re-prompting itself with a request to weight the more recent figure higher and produce a single best-estimate number.
  - **Rationale:** Breaks the T5.6 rule to annotate conflicts with source attribution rather than arbitrarily picking one. Auto-reconciliation destroys provenance and replaces an honest "we don't know which is right" with a made-up single number. Human review on conflicts is the right pattern, not the flaw.
- **D)** The synthesis agent should use a vector store to retrieve semantically similar ARR figures across vendors and compute confidence scores from cosine similarity rather than from value-delta thresholds.
  - **Rationale:** Vector retrieval is the wrong tool for exact numerical comparison — these are structured fields, not free-form text. It also does not address the time-comparability problem: two semantically identical ARR claims from different years would still score as similar and be treated as a match.
