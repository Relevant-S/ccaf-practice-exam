## Question

When implementing your `lookup_order` MCP tool, the backend sometimes returns errors (e.g., "Order not found" or temporary database failures).
What is the correct pattern for communicating these errors back to the agent?

## Options

- **A)** Return a success response with a "status" field indicating the error type
  - **Rationale:** Ad-hoc 'status' fields vary across tools and the model has no standard way to interpret them. isError is the standard.
- **B)** Log the error server-side and return an empty result to avoid confusing the model
  - **Rationale:** Returning empty successes makes the agent think no data exists, rather than that something went wrong — a different and worse confusion.
- **C)** Return the error message in the tool result content with the isError flag set to true
  - **Rationale:** Correct. MCP's designed pattern: put the error text in the content field and mark isError=true. Claude sees both the failure flag and a readable message to reason about.
- **D)** Throw an exception from the tool handler so the agent framework can catch and log it
  - **Rationale:** Uncaught exceptions break the tool protocol and don't give the model anything to reason with.
