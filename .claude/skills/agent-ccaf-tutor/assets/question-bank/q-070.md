## Question

Your repo has a detailed set of testing conventions — which assertion library to use, how to name fixtures, when a test may hit the network. The test files they apply to are spread across more than 30 directories, sitting next to the source files they cover.

You want Claude Code to follow these conventions when it touches a test file, and you do not want the conventions occupying context when it is working on ordinary source files. Every engineer on the team must get them.

What is the right configuration?

## Options

- **A)** Add a `CLAUDE.md` in each directory that contains test files, so the conventions load only when working in those directories.
  - **Rationale:** The scoping instinct is right and directory-level `CLAUDE.md` does exist. But it scales badly here: 30-plus copies to keep in sync, drift whenever someone edits one, and a gap every time a new test directory appears. It also scopes by directory when the real condition is file type — these test files sit beside source files, so a directory-level file loads for the source work too.
- **B)** Put the testing conventions in `~/.claude/CLAUDE.md` and tell each engineer to add the same file locally.
  - **Rationale:** Breaks the sharing requirement. `~/.claude/CLAUDE.md` is user-level: it lives outside the repo, is never shared through version control, and applies to everything that user does across all projects. Relying on each engineer to install their own copy is how conventions silently diverge — the hierarchy mistake the exam guide (T3.1) describes.
- **C)** Put the testing conventions in the root `CLAUDE.md` so they are always loaded and shared with the whole team through version control.
  - **Rationale:** Right about sharing, wrong about scoping. Root `CLAUDE.md` is committed and loaded automatically, so the team does get it — but it is loaded for every task, including ordinary source work where these conventions don't apply. That is exactly the always-on context cost the requirement rules out. `CLAUDE.md` is the right home for universal standards, not conditional ones.
- **D)** Create a file in `.claude/rules/` — for example `testing.md` — with a YAML `paths` field in its frontmatter containing a glob such as `**/*.test.ts`, and commit it.
  - **Rationale:** Correct. A rule with `paths` frontmatter loads only when Claude reads or edits a file matching the glob, so the conventions appear for test work and cost nothing otherwise. Because the glob matches by file pattern rather than location, one file covers all 30-plus directories and any new one added later. And `.claude/rules/` is inside the project, so it ships to the team through version control. The exam guide (T3.3) names this as the preferred choice over subdirectory `CLAUDE.md` files when conventions span the codebase.
