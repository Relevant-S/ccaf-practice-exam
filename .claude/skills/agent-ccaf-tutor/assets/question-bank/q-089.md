## Question

A teammate's agent loop sometimes stops halfway through a task and sometimes runs far too long. Reviewing the code, you find several rules that decide whether the loop continues.

Which TWO of them are anti-patterns that should be removed? (Choose 2.)

## Options

- **A)** The loop continues while `stop_reason` is "tool_use".
  - **Rationale:** Not an anti-pattern. "tool_use" is the protocol signal that the model wants a tool run, so the loop should keep going. Keep this rule.
- **B)** The loop exits when `stop_reason` is "end_turn".
  - **Rationale:** Not an anti-pattern. "end_turn" is the model signalling it has finished. This is the right exit condition. Keep this rule.
- **C)** The loop exits when the assistant's reply contains the word "finished".
  - **Rationale:** Correct. This parses natural language to decide when to stop, which is a named anti-pattern. The model may write "finished" mid-task ("I finished step one") or never write it, which explains both symptoms.
- **D)** Each tool result is appended to the messages before the next request.
  - **Rationale:** Not an anti-pattern. The model needs each result in its context to decide the next step. Removing this would break the loop.
- **E)** The loop exits as soon as a response includes any text block.
  - **Rationale:** Correct. Text being present is not a completion signal — one response can carry a text block and a `tool_use` block together. Exiting on text stops the loop while the model still wants to act.
