## Question

In a multi-agent research system, the coordinator spawns a web search subagent and waits for it to finish. In a later turn it spawns a document analysis subagent. Finally it invokes the synthesis subagent with the one-line task "write the report".

Reports are slow, and they have no source attribution.

Which TWO changes address both problems? (Choose 2.)

## Options

- **A)** Pass the complete findings to synthesis as structured data that separates content from metadata (source URLs, document names, page numbers).
  - **Rationale:** Correct. Subagents do not inherit the coordinator's context. Synthesis only knows what it is given. Attribution survives only if the findings are passed with their sources as structured metadata.
- **B)** Have all subagents write to a shared memory store that synthesis reads from.
  - **Rationale:** This takes control of the information flow away from the coordinator. Subagent communication should go through the coordinator, which keeps it observable and consistent. It also does nothing about the slow, one-after-another spawning.
- **C)** Emit both Task tool calls (search and analysis) in a single coordinator response so they run in parallel.
  - **Rationale:** Correct. Several Task tool calls in one coordinator response run the subagents in parallel. Spawning them across separate turns makes them run one after another, which is why reports are slow.
- **D)** Give the synthesis agent tools to read the other subagents' conversation histories.
  - **Rationale:** This works around the coordinator instead of fixing context passing. Synthesis would dig through raw histories rather than receive clean findings, and the spawning is still sequential.
- **E)** Increase the synthesis agent's `max_tokens`.
  - **Rationale:** `max_tokens` limits how long the output can be. It does not supply missing input, so attribution is still missing, and it does not speed up the spawning.
