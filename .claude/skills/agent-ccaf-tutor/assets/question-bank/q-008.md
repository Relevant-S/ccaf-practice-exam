## Question

After integrating a local MCP server providing code analysis tools (`analyze_dependencies`, `find_dead_code`, `calculate_complexity`), you verify the server is healthy and tools appear in the tools/list response. However, you observe that the agent consistently uses Grep to search for import statements instead of calling `analyze_dependencies`—even when users explicitly ask about "code dependencies." Examining tool definitions reveals:
MCP: `analyze_dependencies` - "Analyzes dependency graph"
Built-in: Grep - "Search file contents for a pattern using regular expressions. Returns matching lines with line numbers and surrounding context."
What's the most effective approach to improve the agent's selection of MCP tools?

## Options

- **A)** Expand MCP tool descriptions to detail capabilities and outputs—e.g., "Builds dependency graph showing direct imports, transitive dependencies, and cycles."
  - **Rationale:** Correct. Tool selection is driven by the descriptions the model sees. A one-line description like 'Analyzes dependency graph' loses against Grep's rich description. Beef up the MCP tool's description.
- **B)** Remove Grep from available tools when the MCP server is connected to eliminate functional overlap.
  - **Rationale:** Crippling a general tool to force adoption of a specialized one punishes other legitimate Grep use cases.
- **C)** Split `analyze_dependencies` into granular tools (`list_imports`, `resolve_transitive_deps`, `detect_circular_deps`) so each has a focused purpose less likely to overlap with Grep.
  - **Rationale:** Splitting is sometimes right, but here the sibling tools would still have weak descriptions. The same selection bug would reappear.
- **D)** Add routing instructions to the system prompt specifying that dependency-related questions should use MCP tools rather than Grep.
  - **Rationale:** Prompt-level routing can help, but the root cause is that the MCP tool's description is thinner than Grep's. Fix the tool descriptions first.
