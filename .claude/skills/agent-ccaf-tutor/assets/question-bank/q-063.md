## Question

Your team wants to set up a CI pipeline (an automated script that runs on every pull request) that has Claude Code review the proposed diff and post inline review comments on the PR. The pipeline runs unattended — no human at a terminal — and must produce structured findings that the pipeline can iterate over to post each as an individual inline comment. The PR was opened by a developer who used Claude Code in the same repo earlier that day to write the changes.

Which configuration best matches Anthropic's recommended architecture?

## Options

- **A)** Inside the CI job, resume the developer's earlier Claude Code session with `--resume <session-name>` to preserve continuity with the code's author, then pipe the output through a JSON formatter to extract findings for the pipeline to post.
  - **Rationale:** Two problems. First, resuming the authoring session brings back the reasoning that justified the code — that session is biased toward thinking the code is correct and is the *least* effective reviewer of its own work. The exam guide (T3.6) recommends an independent review instance. Second, converting prose to JSON after the fact is brittle compared to using `--output-format json` natively.
- **B)** Inside the CI job, spawn a fresh `claude` invocation without `-p`, but pipe `/dev/null` into stdin so it doesn't wait for input. Use the default prose output and parse comment locations with regex.
  - **Rationale:** Routing `/dev/null` into stdin is a workaround for a problem that `-p` solves natively. Regex over prose output is brittle and loses structure that `--output-format json` provides without effort.
- **C)** Spawn a fresh `claude -p` invocation with default text output. Have the pipeline call Claude a second time afterward to convert the prose findings into structured JSON comments.
  - **Rationale:** Wastes a second invocation (cost, latency, another place to fail) doing what `--output-format json` produces natively in the first call. Architecturally redundant.
- **D)** Inside the CI job, spawn a fresh `claude -p` invocation with `--output-format json` (paired with `--json-schema` to constrain the shape). The fresh session reviews the diff on its merits with no authoring bias, and emits structured findings the pipeline can parse and post.
  - **Rationale:** Correct. Three properties are right: (1) `-p` (`--print`) is the non-interactive flag that stops the pipeline hanging on input prompts; (2) `--output-format json` with `--json-schema` gives the pipeline parseable structured findings — file, line, severity, message — that map directly to PR comments; (3) a fresh session, not `--resume`, avoids the self-review bias of the session that wrote the code.
