## Question

A research coordinator runs its search and analysis subagents once, then runs synthesis. The reports are often thin on some subtopics, even though good sources on those subtopics exist.

Which TWO coordinator changes are most effective? (Choose 2.)

## Options

- **A)** Always route every query through the full pipeline twice to be safe.
  - **Rationale:** This doubles the work on every query, including simple ones, and still does not target the missing subtopics. The coordinator should decide dynamically what each query needs.
- **B)** Increase the search agent's result limit from 10 to 100 per query.
  - **Rationale:** More results for the same queries bring more of the same coverage. Subtopics that were never searched for stay thin.
- **C)** After synthesis, have the coordinator check the output for coverage gaps and re-delegate targeted queries to search and analysis before re-running synthesis.
  - **Rationale:** Correct. This is an iterative refinement loop. The coordinator evaluates the result, sends targeted follow-up work for the gaps, and runs synthesis again until coverage is good enough.
- **D)** Partition the research scope so each subagent covers a distinct subtopic or source type, minimizing overlap.
  - **Rationale:** Correct. Giving each subagent its own slice cuts duplicated work and makes it much less likely that a subtopic falls between agents.
- **E)** Let the synthesis agent search the web itself whenever it notices a gap.
  - **Rationale:** This gives synthesis tools outside its role and bypasses the coordinator. Gap-filling should be decided and routed by the coordinator.
