## Question

A skill called `test-triage` runs the full test suite, then groups the failures by suspected cause.

Watching it run: it streams every test name as it goes, and prints the full stack trace for each failure. Last night's run emitted roughly 9,000 lines over 14 minutes, and ended with a five-line verdict: three failure clusters, with one file named as the likely common cause.

Should it have `context: fork`?

## Options

- **A)** No. What it actually returns is a five-line verdict, so there is nothing substantial landing in the main conversation.
  - **Rationale:** The five-line verdict is what the skill *concludes*, not what it *emits*. Without forking, every one of those 9,000 streamed lines lands in the conversation on the way to the verdict — the context cost is the total output, not the final paragraph. Judging fork by the summary is how a 9,000-line skill gets left unforked.
- **B)** Yes. It emits around 9,000 lines on the way to its verdict, and all of it lands in the main conversation unless the skill is forked.
  - **Rationale:** Correct. The question to ask is how much output the skill puts into the main context, and the answer here is the streamed total, not the final summary. Verbose intermediate output plus a small useful result is exactly the profile `context: fork` is for: the skill runs in a separate subagent and only its result returns to the main conversation.
- **C)** No. Stack traces are exactly the detail a developer wants in front of them when triaging failures.
  - **Rationale:** Sounds like good engineering judgment but misjudges the trade-off. A forked skill's result can still include the specific traces that matter, and a single failing test can be re-run in the main conversation when its full trace is needed. What forking prevents is all 9,000 lines landing in the main context whether or not they are needed.
- **D)** Yes. A 14-minute run is long enough that it should not be occupying the main session.
  - **Rationale:** Right answer, wrong reason. Runtime is not what `context: fork` addresses — fourteen minutes is not why this skill needs forking; 9,000 lines is. The duration reasoning would also lead to forking slow skills that print almost nothing.
