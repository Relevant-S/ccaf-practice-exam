## Question

A new teammate reports two problems. Claude Code ignores the team's coding conventions for them, and the team's `/deploy-check` command does not exist on their machine.

You wrote the conventions in your `~/.claude/CLAUDE.md` and the command in `~/.claude/commands/deploy-check.md`.

Which TWO changes fix this? (Choose 2.)

## Options

- **A)** Ask the teammate to run `/memory` each session and paste the conventions in.
  - **Rationale:** `/memory` shows which memory files are loaded. It is a diagnostic tool, not a way to share instructions. Pasting conventions by hand every session is fragile and fixes nothing for the next teammate.
- **B)** Convert the conventions into a personal skill in `~/.claude/skills/`.
  - **Rationale:** Anything under `~/.claude/` is still personal and still not shared. Also, conventions that should always apply belong in CLAUDE.md, not in a skill that runs only when invoked.
- **C)** Move `deploy-check.md` into the repository's `.claude/commands/` directory.
  - **Rationale:** Correct. Project-scoped commands in `.claude/commands/` live in the repository, so every teammate gets them when they clone or pull. `~/.claude/commands/` is personal to one machine.
- **D)** Move the conventions into the project-level CLAUDE.md committed to the repository.
  - **Rationale:** Correct. Instructions in `~/.claude/CLAUDE.md` apply only to that one user and are never shared through version control. The project-level CLAUDE.md is committed, so every teammate loads it.
- **E)** Put the conventions in `.claude/rules/` with `paths: ["~/.claude/**"]`.
  - **Rationale:** Path globs in a rule file match the project files being edited, not the home directory. This rule would never fire, so the conventions would still not load.
