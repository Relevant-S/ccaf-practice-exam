## Question

A customer-support agent for a payments app handles live chat. It can look up account records and apply a set of documented fixes, and it can hand a conversation to a human.

A customer opens with: *"This is the third time this week your app has logged me out mid-payment. It's infuriating."*

They have not asked for a human. The agent can see a known session-token defect affecting their account tier, and there is a documented one-step fix — force a token refresh — that the agent is authorised to apply.

What should the agent do?

## Options

- **A)** Apply the token refresh quietly and report that the issue is resolved, without drawing attention to the frustration.
  - **Rationale:** Right action, missing half the response. The customer expressed frustration; ignoring that while silently fixing the technical problem reads as dismissive and gives them no reason to believe a fourth logout will not happen.
- **B)** Escalate to a human immediately — the customer is clearly frustrated, and frustration is a reliable signal that a case needs human handling.
  - **Rationale:** Sentiment-based escalation, which the exam guide (T5.2) calls an unreliable proxy: emotional tone does not track case complexity. Plenty of furious customers have one-click problems, and plenty of calm ones hit policy gaps. Escalating here hands a solvable problem to a queue and makes the customer wait longer for a fix the agent already had.
- **C)** Acknowledge the frustration, name the cause, say it can be fixed right now, apply the token refresh — and offer a human if the customer would rather have one.
  - **Rationale:** Correct. Frustration is a signal to acknowledge, not a trigger to escalate. The request sits squarely inside the agent's capability and there is a documented fix, so the right move is to resolve it while leaving the door open. Escalate only if the customer asks, or repeats a preference for a person after the offer (T5.2).
- **D)** Ask the customer for the timestamps of the three logouts so the incident can be documented before any fix is applied.
  - **Rationale:** Investigating first only adds delay. The cause is already identified from the account record, so the questions add no diagnostic value. Documentation, if needed, is a back-office task, not a gate in front of the customer's fix.
