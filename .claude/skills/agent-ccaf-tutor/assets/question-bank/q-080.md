## Question

A junior engineer wrote a skill called `cleanup-branches`. It is supposed to read the git branch list, work out which merged branches are stale, and print a recommended deletion list for a human to act on — roughly 40 lines of output.

Last week it did not stop at recommending. On one run it executed the deletions itself.

The team wants the skill's configuration — not just its instructions — to limit it to reading and reporting, never modifying the repository. What should change in its `SKILL.md`?

## Options

- **A)** Add `context: fork`, so the skill runs in an isolated subagent context and cannot affect the main working tree.
  - **Rationale:** Conflates context isolation with sandboxing. Forking keeps the skill's output out of the main conversation. It is not a sandbox: a forked skill still has its normal tool access and still writes to the same working tree.
- **B)** Set `allowed-tools` to a read-only set, so the skill cannot invoke anything that writes files or runs shell commands.
  - **Rationale:** Correct. In the exam guide (T3.2), `allowed-tools` is the frontmatter field for restricting tool access during skill execution. It is the only option here that constrains *capability*. Limit it to reading and searching and the deletion path is closed by configuration, not by asking the skill nicely. *Real-world note (Oct 2026): in current Claude Code, `allowed-tools` only pre-approves the listed tools so they run without a permission prompt; it does not restrict anything. Blocking tools is done with `disallowed-tools`. The exam guide uses the older meaning, so answer the exam the guide's way.*
- **C)** Move the skill from `.claude/skills/` to `~/.claude/skills/` so it is personal and can no longer affect teammates.
  - **Rationale:** Confuses scope with permission. Project scope versus user scope decides who can invoke the skill and whether it ships through version control. It changes nothing about what the skill can do once it runs — it would still delete branches.
- **D)** Add `argument-hint` requiring an explicit `--confirm` flag before any deletion happens.
  - **Rationale:** `argument-hint` tells the user what arguments the skill expects when they invoke it. It is a usability aid, not an authorization gate — nothing enforces that the skill checks the flag before acting.
