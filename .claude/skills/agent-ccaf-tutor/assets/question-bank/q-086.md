## Question

Your CI review bot posts findings on every pull request. Developers have started ignoring it. Analysis shows the "comment accuracy" category has a 60% false-positive rate, while the security and bug categories are mostly accurate. The prompt currently says "be conservative and only report high-confidence findings."

Which TWO changes are most effective? (Choose 2.)

## Options

- **A)** Temporarily disable the high-false-positive category while you improve its prompt.
  - **Rationale:** Correct. One noisy category drags down trust in the whole bot, including the accurate security and bug findings. Switching the noisy category off for now restores trust in the categories that work, while you rewrite the prompt for the broken one.
- **B)** Strengthen the instruction to "only report findings you are very confident about."
  - **Rationale:** This is the same vague instruction, only louder. General instructions like "be conservative" or "only report high-confidence findings" do not improve precision. The model still has no rule for what counts as a real problem.
- **C)** Post a finding only when the model self-reports confidence of 8/10 or higher.
  - **Rationale:** Self-reported confidence is poorly calibrated. The model can be confidently wrong, so a threshold on its own score filters the wrong things. Precision comes from clear criteria, not from confidence-based filtering.
- **D)** Show more findings per pull request so developers see the bot is thorough.
  - **Rationale:** More findings means more false positives. Developers who already ignore the bot will ignore it faster. This makes the trust problem worse.
- **E)** Replace the vague instruction with explicit criteria for what to report and what to skip (for example, flag a comment only when its claimed behavior contradicts what the code actually does).
  - **Rationale:** Correct. Specific, categorical criteria tell the model exactly which issues count. "Flag a comment only when it contradicts the code" is testable; "be conservative" is not. This is the direct fix for low precision.
