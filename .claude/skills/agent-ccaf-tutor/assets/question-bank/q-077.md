## Question

Cutting a release at a company is a 40-step procedure: bump the version, regenerate the changelog from merged PRs, tag, run the smoke suite against staging, update three docs pages, post to the release channel. It happens roughly twice a month, always by a different engineer, and step one needs the target version number.

The team wants Claude Code to drive it, for anyone on the team.

Where does the procedure belong?

## Options

- **A)** In the project's root `CLAUDE.md`, so it is committed and every engineer has it available.
  - **Rationale:** Right about distribution, wrong about cost. `CLAUDE.md` is always-loaded memory — those 40 steps would occupy context in every session, including the hundreds of ordinary coding tasks that have nothing to do with releasing. `CLAUDE.md` is for universal standards that should shape all work; a procedure used twice a month is the opposite.
- **B)** In `.claude/rules/release.md` with a `paths` glob so it loads only when relevant.
  - **Rationale:** The right instinct about conditional loading, applied through a mechanism that cannot fire here. Path-scoped rules load when Claude reads or edits files matching the glob — but cutting a release is not tied to one particular file. There is no path condition to write, so any glob either never matches or matches work that is not a release.
- **C)** As a skill in `.claude/skills/`, committed to the repo, with `argument-hint` for the version number.
  - **Rationale:** Correct. This is the skills-versus-`CLAUDE.md` choice in the exam guide (T3.2): skills are on-demand and task-specific, loaded when invoked and costing nothing otherwise, which fits a twice-monthly 40-step procedure exactly. Putting it in `.claude/skills/` inside the repo ships it to the whole team through version control, and `argument-hint` tells whoever invokes it that a version number is expected — so an engineer running their first release knows what the skill needs instead of guessing.
- **D)** As a personal command in `~/.claude/commands/`, shared with the team by pasting it into the team wiki.
  - **Rationale:** Wrong scope. `~/.claude/commands/` is user-level — outside the repo and never shared through version control — so "shared via the wiki" means every engineer hand-installs a copy that drifts from the next. A procedure the whole team must run belongs in the project, not in each person's home directory.
