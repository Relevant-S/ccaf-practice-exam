## Question

Your extraction pipeline validates its output with Pydantic and retries when validation fails.

Which THREE statements about the retry and feedback design are correct? (Choose 3.)

## Options

- **A)** Retries can fix format problems, like a date in the wrong format, when the correct value is in the document.
  - **Rationale:** Correct. The information is present in the source; the model only needs to be told what was wrong. Format and structure errors are the kind a retry can fix.
- **B)** Retry the identical request unchanged until it passes, since outputs vary between runs.
  - **Rationale:** Without the error feedback the model does not know what to change, so the same mistake usually repeats. Blind retries waste calls.
- **C)** A strict schema via `tool_use` removes both syntax errors and semantic errors such as line items not adding up to the total.
  - **Rationale:** A strict schema removes syntax errors only. Semantic errors — values that don't sum, values in the wrong field — still pass the schema and need separate validation.
- **D)** Retries won't help when the needed value only exists in a document that wasn't provided.
  - **Rationale:** Correct. No retry can produce information that is not in the input. These cases need a different path, such as a null value or a human check.
- **E)** If a retry fails, make the field required so the model has to fill it.
  - **Rationale:** When the value is genuinely absent, a required field forces the model to invent one. That turns a visible gap into a hidden error.
- **F)** The retry request should include the original document, the failed extraction and the specific validation error.
  - **Rationale:** Correct. This is retry with error feedback. The model sees the source, what it produced and exactly what failed, so it can correct the specific problem.
