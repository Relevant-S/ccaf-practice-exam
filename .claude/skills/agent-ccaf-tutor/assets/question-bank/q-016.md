## Question

The agent verifies customer identity through a multi-step process before resetting passwords. During testing, you notice that after the customer answers the third verification question, the agent asks them to provide their name again, as if the earlier exchange never happened.
What's the most likely cause of this behavior?

## Options

- **A)** The conversation history isn't being passed in subsequent API requests.
  - **Rationale:** Correct. The API is stateless. Each request must include the full messages array. If you only send the latest turn, the model has no memory of earlier ones — exactly the 'ask for the name again' symptom.
- **B)** Claude's memory retention is limited to two conversational turns by default, requiring explicit configuration to extend it.
  - **Rationale:** No such default limit exists. Context is bounded by the window, and history length is under your control.
- **C)** The verification tool is clearing the agent's internal state after each successful validation step.
  - **Rationale:** Tools don't clear agent state — conversation state lives in the messages array you send.
- **D)** The prompt lacks instructions telling Claude to remember information across multiple exchanges.
  - **Rationale:** Memory across turns isn't achieved by an instruction — it comes from passing the prior turns into the next request.
