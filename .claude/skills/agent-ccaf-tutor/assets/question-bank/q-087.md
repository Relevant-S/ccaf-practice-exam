## Question

A batch step processes scanned documents with three extraction tools: `extract_invoice`, `extract_receipt` and `extract_contract`. The document type is not known in advance, and any of the three may be the right one — the model should pick whichever fits the document.

The problem: about 6% of the time the model replies in prose ("This appears to be a receipt from…") instead of calling any tool, and the downstream parser fails.

What is the most effective fix?

## Options

- **A)** Force `{"type": "tool", "name": "extract_invoice"}` on every call.
  - **Rationale:** Forcing one named tool guarantees a tool call, but always the same one. Receipts and contracts would be pushed through the invoice extractor and come out wrong.
- **B)** Keep `tool_choice` as "auto" and add "ALWAYS respond with a tool call" to the system prompt.
  - **Rationale:** With "auto" the model is still allowed to answer in text. A prompt instruction lowers the failure rate but cannot remove it. A setting exists that guarantees the behavior, so relying on wording is the weaker choice.
- **C)** Force one specific tool on the first call, then switch back to "auto".
  - **Rationale:** That pattern fits when one step must run first (for example, extraction before enrichment). Here there is no single right first tool, and once back on "auto" the model can still reply in prose.
- **D)** Set `tool_choice` to "any".
  - **Rationale:** Correct. "any" means the model must call a tool but chooses which one. That removes the prose replies and still lets the model pick the extractor that fits the document — exactly the requirement. *Real-world note (Oct 2026): some of the newest Claude models reject "any" and forced tool choice in certain modes. The exam guide teaches "any" for this case, so answer the exam the guide's way.*
