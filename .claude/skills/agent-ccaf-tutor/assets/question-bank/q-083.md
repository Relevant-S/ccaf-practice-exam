## Question

An invoice-extraction pipeline outputs field-level confidence scores. Before going live, the team validated accuracy per document type and per field against a labeled set, then turned on auto-approval for high-confidence extractions. That has been running for six months, and roughly 85% of documents now skip human review entirely.

Two things worry the team. Vendors keep changing their invoice layouts, and the mix of document types has drifted since the original validation.

They want ongoing assurance that the auto-approved stream is still accurate. What should they build?

## Options

- **A)** Review every extraction that lands just above the auto-approve threshold, since those are the riskiest.
  - **Rationale:** The reasoning is half sound — borderline cases do carry more risk per document. But it only ever inspects a thin band near the cut-off. A new vendor layout that the model misreads *confidently* passes at 0.98 and is never sampled. Boundary review measures where the threshold sits; it cannot detect new failure modes above it.
- **B)** Track the share of documents falling below the threshold over time and investigate if it starts rising.
  - **Rationale:** A proxy that misses the failure being asked about. A rising low-confidence rate is a useful early alarm for one kind of drift, but the dangerous case is the opposite: high confidence, wrong answer. That shows up nowhere in this metric.
- **C)** Have the model flag any document whose layout it does not recognise, and route those to human review.
  - **Rationale:** Relies on the model's own judgment of itself, which is an unreliable proxy. A model that misreads a new layout generally does not know it has done so — that is what makes the failure dangerous. Measurement of the automated stream has to come from outside the model.
- **D)** Randomly sample auto-approved extractions — stratified across document types and fields — and have humans check them on a continuing basis.
  - **Rationale:** Correct. The auto-approved stream is the one nobody looks at, so it is the one that needs deliberate measurement. Random sampling keeps the estimate unbiased; stratifying stops low-volume document types from vanishing from the sample, which matters because that is where a new layout often shows up first. The exam guide (T5.5) names stratified random sampling of high-confidence extractions for measuring error rates and detecting new error patterns. This gives a live error rate for the automated path rather than an assumption about it.
