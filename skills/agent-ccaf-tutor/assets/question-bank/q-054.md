## Question

After your daily batch of 10,000 documents completes, 300 documents (3%) failed with " `context_length_exceeded` " errors. The results file identifies each failure by `custom_id`.
What's the most cost-effective approach to process these failures?

## Options

- **A)** Increase the `max_tokens` parameter for the 300 failed documents and resubmit them in a new batch
  - **Rationale:** `max_tokens` controls output length, not input length. It doesn't solve `context_length_exceeded`, which is about the combined input-plus-output budget.
- **B)** Resubmit only the 300 failed documents after chunking them into smaller pieces, then combine the partial extractions
  - **Rationale:** Correct. Targeted, and it addresses the actual cause (input too long). Chunk the oversized docs, extract per chunk, then merge — minimum tokens, fixes the specific failure mode.
- **C)** Resubmit the entire 10,000 document batch using a model tier with a larger context window
  - **Rationale:** Expensive (reprocessing 9,700 successes) and may still fail on truly outsized documents.
- **D)** Reprocess the entire batch with prompt caching enabled to reduce the cost of retrying requests with identical system prompts
  - **Rationale:** Re-running 10,000 successful documents to solve 300 failures is wasteful regardless of caching savings. And caching doesn't fix the length-exceeded error.
